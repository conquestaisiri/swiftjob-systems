# Infrastructure and deployment

The active deployment is Cloudflare Pages (`swiftjob-systems`) with a Pages Function proxying to the Hono Worker (`swiftjob-workers-api`), Neon PostgreSQL, R2, and Resend. The former private B2/combined MSI path is retired. Provider inventory confirmed access and recorded deployment metadata without emitting secrets.

CI now installs the pinned pnpm version explicitly, uses boolean `allowBuilds` values for `sharp` and `workerd`, runs frozen installs, executes isolated regressions with their standalone runtime dependencies, and fails when a required Worker secret is absent. Hosted CI remains configured with the migrated domain secrets; production deploy jobs remain gated to `main`. Worker and Pages deploy jobs remain separate. The latest Pages production deployment is `b0ffae7a.swiftjob-systems.pages.dev` under project `swiftjob-systems`, and `https://swiftjob.online` is the active custom domain.

Post-deploy checks on `swiftjob.online`: `/api/healthz`, `/api/jobs`, and `/api/public-stats` return 200 with security headers; protected candidate/admin routes reject anonymous access; admin login and read-only admin endpoints work with the migrated admin address; dynamic `/sitemap.xml` returns XML with 95 live public-job URLs and new-domain URLs; `/robots.txt`, canonical metadata, the logo asset, and legal pages use the new hostname; controlled referral, application-confirmation, and magic-link messages report `delivered` and render in the owner mailbox; Cloudflare Email Routing now handles the HR receiving route. Historical provider bounces remain recorded separately. Migration `013_application_idempotency.sql` was applied additively and existing job/application counts were unchanged.
